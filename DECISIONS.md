# Decisions

- Phase 0 uses `compileSdk = 35` and `targetSdk = 35`, matching the plan's example configuration.
- **No synthetic-weather decision (current):** remove demo mode, simulated clocks/scenarios, generated weather values, bundled weather databases/spreadsheets, canned weather payloads, and fabricated weather tests. Open-Meteo Weather, Air Quality, and Marine responses are the only weather inputs; offline behavior may use only exact cached provider responses or user-prepared packs of those responses. If no valid data exists, show unavailable. This supersedes earlier Demo/bundled-dataset decisions.
- Phase 1 uses version name `1.1` and version code `2`; the verification screen reads both from generated build metadata.
- Persona IDs are persisted as an ordered comma-separated string in `persona_weather_prefs`; card-disabled IDs use a set.
- Phase 2 increments the app to version name `1.2` and version code `3`; the verification screen always reads the current values from generated build metadata.
- Saved routes are user-defined ordered locations/stops with verified coordinates and user-supplied ETAs. No weather is available offline unless an exact, in-coverage provider response was cached or explicitly downloaded into a trip pack.
- Travel alerts surface severe weather advisories, but do not claim airline flight-status integration; no flight schedule or disruption feed is bundled.
- Commuter road status is derived from forecast rain, fog, and visibility; live traffic data is not available without a traffic feed.
- Agriculture guidance uses only variables actually returned by the provider; missing soil/rain inputs mean unavailable guidance, not a substituted recommendation.
- Open-Meteo Weather, Air Quality, and Marine are the sole weather sources. Successful responses are cached privately by locality/endpoint; request failures use only the exact last-good response within its forecast coverage, otherwise show unavailable.
- Outdoor-fitness sunrise and sunset use Open-Meteo's daily `sunrise`/`sunset` values in the requested locality timezone. Beach wave heights use Open-Meteo Marine; visible high/low tide timings are hourly sea-level forecast extrema and must be described as estimates, not navigation guidance. WorldTides was reviewed for dedicated tide extremes, but requires a per-user API key and credits and is not integrated under the current Open-Meteo-only source decision.
- The event-planner comfort score is an explainable 0–100 estimate combining forecast rain probability, AQI bands, and cold/heat penalties; its tuning thresholds are in `Tuning.kt`.
- Open-Meteo values are model forecasts, not station observations. Unavailable pollen or other fields remain unavailable; AQI is modeled CAMS output, and modeled marine data is not suitable for navigation.
- Time uses the current `Asia/Kolkata` hour. Live weather/AQI horizon and model identity come from each provider response and must be labeled; do not assume a fixed forecast horizon.
- Open-Meteo requests use JDK `HttpURLConnection` to preserve dependency constraints. About credits Open-Meteo, CAMS, and the marine model providers; the free service is intended only for non-commercial evaluation.
- Calendar integration uses Android's native Calendar Provider with `READ_CALENDAR` permission, not Google API keys or a custom OAuth flow. For each selected event, the user confirms indoor/outdoor context and a verified forecast locality; raw calendar location text stays on-device. The app evaluates configured persona rules across the full event duration, bounding lookahead to that duration. Outdoor events use applicable rules; indoor events receive supported outdoor AQI advice only, clearly caveated. Events outside provider coverage are unavailable, never extrapolated.
